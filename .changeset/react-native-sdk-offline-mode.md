`ConfigDirectorProvider` accepts `mode="offline"`, a mode in which the client never connects to ConfigDirector and sends nothing, and a new `values` prop. In offline mode the client serves `values`, one value per config key, to every context, with the config type of each value decided by the value itself, or the in-code default values when no `values` are given; returning to the foreground or regaining the network opens no connection. A change to the `context` prop stores the new context, keeps the values, and returns the status to `ready`. `sdkKey` is now optional: `<ConfigDirectorProvider mode="offline" values={{ "new-checkout": true }}>` needs no key, while every other mode still fails without one as before. A value such as `null`, or `values` given in `streaming` or `polling` mode, keeps the client from becoming ready: every config returns its in-code default value and the provider's status stays `loading` and reports a `ConfigDirectorInitializationError` as an unhandled promise rejection. `createClient` takes the same `connection: { mode: "offline", values }` options; its key parameter is still required and is not used in offline mode. The `OfflineValues` and `OfflineValue` types describe the values.
