"@configdirector/nextjs-sdk": minor

The client `ConfigDirectorProvider` accepts a `client` prop, an existing `ConfigDirectorClient` to provide instead of building one from `sdkKey`; its props are now `ConfigDirectorClientProviderProps`, the union of `ConfigDirectorProviderOptions` and `ConfigDirectorClientProviderClientProps` (which also takes `initialConfigs`), and the `/client` entry exports both types. A given client is provided on the first render, so `useClient` no longer throws there, and the provider reports the ready status at once when the client is ready. A provider never disposes a client it was given, only one it built. It does not initialize a given client that is ready or initializing, updates the context only when the `context` prop is given and differs from the client's context, registers `hooks` given with a `client` while it is mounted, and removes every handler it registered when it unmounts. The `context` prop is compared by deep equality, so a new object with the same contents no longer reconnects. A changed `client` prop after mount is ignored with a warning.

Added the `@configdirector/nextjs-sdk/client/testing` entry point with `createTestClient({ values })` and `installTestClient(testClient)`, and the `@configdirector/nextjs-sdk/server/testing` entry point with `createTestClient({ values })` for the server SDK and `installServerTestClient(testClient)`, which puts the test client's client where `register()` puts the server singleton and returns a function that restores the previous one. Both entries export `ConfigDirectorValidationError` and `ConfigDirectorConnectionError` at runtime, and the package has `typesVersions` mappings for the new subpaths.
